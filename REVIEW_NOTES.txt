FrameLock v2 — source review notes (2026-11-20)

Changes in this reviewed package
- Hardened D3D12 worker-slot lifetime: every normal and discarded readback job must confirm its fence before its slot can be reused. If fence completion cannot be confirmed, the slot's GPU resources are retired rather than released/reused.
- A D3D12 readback slot is now fence-checked even when WIC initialization failed.
- Kept the D3D12 readback Map range as [offset, offset + size).
- Corrected OpenGL swap hooks to use GDI32!SwapBuffers and OpenGL32!wglSwapLayerBuffers.
- Changed the self-test to detect identical adjacent frames (the stated requirement), not any repeated hash anywhere in the sequence.
- Added explicit standard-library includes and an encoder-thread startup check.
- Added a manual GitHub Actions workflow for MSVC x64 and Win32 builds.
- Updated README to describe actual clock-hold/watchdog behavior and remaining limitations.

Important review correction
- D3D11 GetBuffer(0) is intentional and correct for D3D11's automatic back-buffer identity rotation. Explicit GetCurrentBackBufferIndex tracking is required for D3D12, and this source uses it there.

Not verified
- This package has NOT been compiled. The review environment has clang-cl but no Windows SDK; a syntax-only attempt stops at the missing windows.h header. MSVC/Windows SDK compilation remains required.
- No D3D11 or D3D12 game runtime test has been performed. The 120-frame self-test must be run against a moving scene separately for each API.
- D3D12's fallback to the last observed DIRECT queue remains experimental. It is not proven to be the queue used to present a given swapchain; resource ordering can therefore be wrong in this fallback case.
- The capture/render thread can block under staging-slot or bounded-queue backpressure. D3D9/OpenGL remain synchronous for readback. D3D12 MSAA and Vulkan are unsupported.
- Locked-clock mode hooks selected Windows clock APIs; it is not an engine-level simulation step API. Its watchdog only recognizes sustained polling of a hooked clock.

Build route
- On Windows, use build.bat with Visual Studio 2022, Desktop development with C++, CMake, and internet access for MinHook FetchContent.
- Without a local compiler, upload this folder's contents to a GitHub repository (preserving .github/workflows/windows-build.yml), then run Actions -> Build FrameLock for Windows. Download the FrameLock-Windows artifact.
